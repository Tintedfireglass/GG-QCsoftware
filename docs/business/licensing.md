# License & Trial Management

> **Audience:** Sales, Finance, Onboarding teams  
> **Classification:** Internal

---

## Overview

Pramaan uses a **license key system** to authenticate CLI/desktop clients and control access to QC submission features. Additionally, a **free trial system** allows potential customers to evaluate the product for a limited period.

---

## License Key Types

| Type | `type` value | Description |
|---|---|---|
| **Single Use** | `single_use` | One activation for one machine |
| **Bulk** | `bulk` | Multiple activations, configurable max uses |
| **Demo** | `demo` | Generated by Employees for sales demos; linked to a customer name |

---

## License Key Fields

| Field | Description |
|---|---|
| `key` | The license key string (UUID format) |
| `type` | `single_use`, `bulk`, or `demo` |
| `max_uses` | Maximum number of machines that can activate with this key |
| `current_uses` | Current number of activations |
| `is_active` | Can be deactivated by an admin to revoke access |
| `expires_at` | Optional expiry date; null = never expires |
| `demo_customer_name` | For demo keys: name of the prospect customer |
| `created_by` | User ID of who created the key |

---

## License Activation Flow

1. **Technician enters license key** in the CLI or Windows app
2. **App calls** `POST /api/auth/login` with the license key + machine identity (serial, MAC address, computer name)
3. **API validates** the key, increments `current_uses` if valid, and returns a **JWT token**
4. **JWT token** is stored locally (`~/.pramaan/session.json` on Linux) and used for all subsequent API calls
5. **Token expiry** — the app re-authenticates automatically on the next background heartbeat

---

## Machine Identity

Each device is assigned a unique integer **Device ID** based on this priority:

1. BIOS serial number (preferred — factory-burned, highly reliable)
2. MAC address (fallback)
3. Computer name (last resort)

Device IDs are stored in a local registry:
- **Linux/CLI:** `~/.pramaan/` directory
- **Windows:** `%ProgramData%\Pramaan\device_registry.json`

Once assigned, a Device ID remains stable through reboots and OS reinstalls (as long as the serial number doesn't change).

## Free Trials

Free trials allow devices to submit limited QC data without a paid license.

### Trial Properties
| Property | Value |
|---|---|
| Duration | **7 days** (set at creation via `NOW() + INTERVAL '7 days'`) |
| Scope | One machine per trial (tied to a composite fingerprint: serial + MAC + hostname) |
| Email | One email address per trial, globally blocked from being reused on another device |
| Features | Full QC submission, heartbeat reporting |
| Role | `TrialUser` JWT scope |
| Revocation | Can be revoked by SuperAdmin at any time |

### Trial Flow
1. User provides their email + machine serial number to start a trial
2. API (`POST /api/auth/trial`) validates: machine fingerprint not already trialled, email not already used on another device
3. Trial record is created with `trial_end_utc = NOW() + INTERVAL '7 days'`; email is blocked globally
4. JWT `TrialUser` token is returned and stored locally
5. After trial expiry (or revocation), the device must activate with a paid license key — no extensions

---

## Background Heartbeat

Devices with an active license or trial session send a **heartbeat every 4 hours** via a systemd timer (on Linux) or Windows Task Scheduler. The heartbeat:

- Refreshes the license validation
- Confirms the device is online
- Updates `last_seen` timestamp on the machine record

If the heartbeat fails (e.g., invalid license), the local session is cleared and the device must re-authenticate.

## Managing License Keys (Dashboard)

License keys are managed under **Dashboard → Licenses**.

| Action | Who Can Do It |
|---|---|
| View all keys | SuperAdmin, Refurbisher, Reseller |
| Create `single_use` / `bulk` keys | SuperAdmin, Refurbisher, Reseller |
| Create `demo` keys | SuperAdmin, Employee, Refurbisher, Reseller |
| Deactivate a key | SuperAdmin, Refurbisher, Reseller |

---

## License Credits

Some user accounts have a **`license_credits`** balance. Credits represent the number of license keys they are permitted to create. Credits are managed by SuperAdmin and are decremented when a user creates new license keys.
