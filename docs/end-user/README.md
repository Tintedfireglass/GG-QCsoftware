# End-User Documentation

This folder contains practical, end-user-facing documentation for **Pramaan**, aimed at day-to-day operators:

- **QC Technicians**: run checks on devices and generate certificates.
- **QC Leads / Operations**: audit results, handle exceptions, and track productivity.
- **Resellers / Clients / Enterprise teams**: review results and track device history over time.
- **Admins**: manage users, access, and licensing (role-based).

If you’re looking for product positioning or technical implementation details, use the Business/Engineering docs in `docs/business` and `docs/engineering`.

---

## How the system fits together (quick mental model)

Pramaan has two main user surfaces:

1) **Windows Desktop App (WPF)**  
Used on the machine being certified. It runs automated diagnostics + guided manual tests, then creates a certificate/report. If the app is activated/logged in and the server is reachable, it also **submits** the report to the central database.

2) **Web Dashboard**  
Used to view results across devices, teams, and time; track machine histories; manage users and license keys; and print/export certificates.

When a report is submitted successfully, it becomes visible in the Web Dashboard.

## Glossary (common terms)

- **QC Run / Test**: one complete certification attempt for a device (has a unique Test ID).
- **Machine**: a physical device tracked over time (may have many QC runs).
- **Grade / Score**: the overall health result (A+/A/B/C etc.) used for certification and sorting.
- **Certificate / Report**: the printable QC document generated by the desktop app and/or dashboard.
- **Health ID**: a public verification identifier (often represented as a QR code).
- **Activation / License Key**: allows the desktop app to submit results to the server and unlock features, depending on your plan.
